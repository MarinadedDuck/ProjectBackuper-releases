What's New in 1.04

Hotfix for the v1.03 symlink mode — project files now open directly from snapshot folders.

  • Fixed: In symlink mode (used for NAS destinations that don't support hardlinks), double-clicking a project file in a snapshot folder used to show a generic "alias" icon and refuse to open in Premiere / After Effects / Photoshop. macOS was inspecting the symlink target — the file inside .projectbackuper/store/ — which had no extension. It couldn't determine the file type.

    Now the store object's filename includes the original extension (e.g. store/ab/abcd1234….prproj instead of store/ab/abcd1234…), so the symlink resolves to a target with a recognizable UTI. Double-click works normally. Hardlink mode is unaffected, but store filenames are now consistent across both modes.
  • Note for existing NAS users: Your store objects from v1.03 will become orphans after the first v1.04 backup pass (the new pass re-copies under the new naming). The next retention run will GC them automatically — no manual cleanup needed. Your store will roughly double in size briefly and then return to normal.

What's New in 1.03

NAS-compatibility release: Project Backuper now works on SMB shares that don't support hardlinks (QNAP and Synology over SMB).

  • New: Symlink fallback for destinations that reject link(2). Picker probes at destination-pick time and falls back to relative symbolic links automatically. Info dialog tells you when the fallback engages; Settings → Setup shows the current link mode under the destination path.
  • New: If neither hardlinks nor symlinks work on the volume, the destination is refused with a clear error.

What's New in 1.0 — Initial Release

First public release. Menu-bar app that backs up Adobe project files (Premiere Pro, After Effects, Photoshop, Illustrator) on a schedule, with hardlink-based deduplication.

  • Time Machine-style snapshot history (30 min – 24 h cadence).
  • Content-addressed store — unchanged files cost zero extra disk space across snapshots.
  • "Last Backup" symlink at the destination root.
  • Activity Log with timings, byte counts, and snapshot IDs.
  • LucidLink-aware fast enumeration.
  • Simple and tiered retention policies.
  • Sparkle auto-updates with EdDSA signing.
