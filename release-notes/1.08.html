What's New in 1.08

Hotfix for the Restore Files panel introduced in v1.05.

  • Fixed: "Restore Files…" and "Restore to Original Location" failed with ditto: invalid option -- L on every file in v1.05 through v1.07. The implementation was calling /usr/bin/ditto -L, but ditto doesn't have a -L flag — that was a confusion with cp -L. The copy path now uses FileManager.copyItem against the symlink-resolved source, which does exactly the right thing in both hardlink mode and symlink mode: it follows the symlink (or just opens the file, in hardlink mode) and writes a real regular file at the destination with the original name.
  • Test coverage added: Two new tests exercise the restore copy primitive directly — one for a regular-file source, one for a symlink-into-store source. The earlier broken implementation slipped through because no test had ever called the restore copy function. 36 → 38 tests, all green.
  • Updated: The ⓘ Help button in the Restore view now shows the working Terminal equivalent (/bin/cp -RL) instead of the broken ditto -L.
