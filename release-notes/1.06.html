What's New in 1.06

Three Restore Files improvements aimed squarely at the symlink-mode workflow where double-clicking from Finder makes Adobe apps see the store's hashed filename instead of the original.

  • New — Quick Open: Double-click any row in the Restore window to copy that one file into a managed caches folder and open it with its default app. Premiere / After Effects / Photoshop / Illustrator receive the file under its real name (e.g. Edit.prproj), so the title bar, recent-files list, and project window all show the right thing. The caches folder is cleaned by macOS under disk pressure — you don't have to manage it.
  • New — "Open files after restoring" checkbox in the Restore window. Tick it before clicking Restore To… and every restored file opens with its default app once the copy finishes. (Asks for confirmation above 5 files to avoid launching a horde of windows.)
  • Safer: Restore now never overwrites existing files at the chosen destination. Files with name collisions are automatically renamed " (1)", " (2)", … following Finder's "Duplicate" convention. The completion alert reports how many were renamed so you can spot conflicts at a glance.
  • Hint surfaced: The Restore window now shows a tip under the table reminding you that double-click opens a file directly, and the ⓘ help button has been expanded to cover the new behaviors plus the equivalent ditto commands for Terminal users.

Why this matters for the Adobe-name issue: macOS resolves symlinks before handing the URL to the receiving app, so a double-click from a symlink-mode snapshot folder shows the resolved path (store/ab/abcd….prproj) instead of Edit.prproj. There's no public API to override that. The fix is to always open the file from a real-file location with its original name — which is exactly what Quick Open and the post-restore auto-open do.
